# Новый интерфейс на основном адресе

Главная страница https://app8016190941.tgcloud.ai/ загружает React непосредственно на этом адресе, без редиректа и iframe. APP_URL и настройки BotFather остаются на корневом адресе. Ранее предложенное изменение APP_URL на /react/ для этой схемы не требуется.

web/index.html читает react/manifest.json, загружает CSS и точку входа последней Vite-сборки. Манифест генерируется при npm run build. Старые сборки без manifest.json не подходят: обязательна повторная сборка перед публикацией. При ошибке загрузки пользователь видит сообщение и ссылку на legacy.html.

Старый интерфейс сохранён на https://app8016190941.tgcloud.ai/legacy.html . Его скрипты и стили остаются рядом. Vite-плагин меняет только старые fallback-строки '../index.html' в main.jsx и ui.jsx на '../legacy.html' при сборке, чтобы кнопка старой версии не возвращала пользователя в новый интерфейс. После будущей модульной переработки маршрутов этот совместимый transform можно удалить, изменив исходные fallback-константы.

Перенос ещё не полон: новости, клубы, библиотека, экзамены, администрирование, изменения расписания и расширенные настройки находятся в старом интерфейсе. Главная версия также сохраняет предупреждение о незавершённом переносе.

## Сборка и деплой

```sh
cd ~/schedule-src
git checkout tgcloud
git pull --ff-only origin tgcloud
cd serverless/frontend
npm install && npm run build
```

Продолжайте только при успешной сборке:

```sh
cd ~/schedule-src/serverless
test -s web/react/manifest.json && test -s web/react/index.html && npx --yes --package=@tgcloud/cli tgcloud push
```

CLI должен быть заранее настроен и авторизован для нужного проекта. push публикует проект по его конфигурации, включая бэкенд и статику; не запускайте из неполной локальной копии. Изменений схемы БД нет. Проверяйте основной адрес внутри Telegram, чтобы работал Serverless bridge. Обычный браузер покажет новый интерфейс, но без Telegram Serverless он не сможет получить данные.

## Service worker

Кеширующий worker заменён на network-only worker. Он удаляет только известный кеш schedule-v51, не очищает localStorage/sessionStorage и не трогает прочие кеши. Это временно отключает офлайн-оболочку ради корректного обновления основной страницы. Существующие ограниченные кеши API в React остаются. Новый register-sw.js проверяет обновления; старые уже открытые страницы могут потребовать полного закрытия и повторного открытия Mini App после активации нового worker. Гарантии мгновенного обновления всех старых клиентов нет.

## Проверка и откат

Проверьте корень, /index.html, /react/index.html и /legacy.html, загрузку CSS/JS, кнопки старой версии в расписании/ДЗ/ошибке, роли студента/ассистента, выбор потока и открытие из Telegram. Ветка /react/ остаётся дополнительной точкой входа, главная — корень.

Для срочного доступа используйте /legacy.html. Для отката основного сайта восстановите web/index.html из web/legacy.html в отдельном проверенном коммите и повторно опубликуйте. Старые JS/CSS не удаляются. Ассистент не выполнял npm-сборку, браузерные проверки или деплой этого изменения. Этот документ заменяет прежние указания README о сохранении старой главной страницы.
