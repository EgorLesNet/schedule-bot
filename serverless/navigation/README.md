# Нижнее меню на Glisse

Изолированный React TabBar из glisse@0.4.3. Остальные экраны остаются на существующем JavaScript.

Перед синхронизацией web/ в проект Telegram Serverless:

```sh
cd ~/schedule-src/serverless/navigation
npm install --no-audit --no-fund --package-lock=false
npm test
npm run build
```

Сборка создаёт в serverless/web/ файлы glisse-nav.js, glisse-nav.css и glisse-notices.txt. Они локальные и не коммитятся; при каждом деплое сначала выполняйте сборку, затем rsync.

Проверьте наличие всех трёх файлов перед rsync. При ошибке сборки остановитесь, не публикуйте неполное обновление.

React управляет только #glisse-tabs. Переключения передаются штатным кнопкам #tabs, поэтому обработчики вкладок и повторных нажатий остаются прежними. Исходное меню скрывается только после успешной инициализации Glisse. При отсутствии bundle или ошибке React остаётся обычное меню. navpill.js больше не подключается, чтобы исключить двойную обработку жестов.

CDN и runtime-загрузки npm-пакетов не используются. Service worker кэширует локальные файлы меню, если они доступны; без них основная оболочка продолжает работать. Полный оптический эффект зависит от WebView: Safari может показывать размытие и блики без полного преломления. data-glisse-backdrop на весь экран намеренно не ставится, чтобы не клонировать содержимое расписания.

Зависимости фиксированы в package.json; транзитивный lockfile пока не включён. Настоящую npm-сборку, внешний вид, drag, клавиатуру, тёмную тему и офлайн-запуск необходимо проверить в браузере и Telegram WebView.
